# QuackQuota Standard Review Workflow

## What this is

Every time DeepSeek Agent finishes a development task, instead of telling you
"done" and leaving you to collect patches, logs, and repo snapshots, the agent
generates one file: `QuackQuota-<TaskName>-Review.zip`. You upload that single
ZIP to GPT-5.6 for review.

## Workspace Path Enforcement (BLOCK-1)

Before starting any task, the agent MUST verify that it is operating in the
correct worktree:

1. Run `Get-Location` (or `pwd`) — must equal the contract-specified repository path.
2. Run `git rev-parse --show-toplevel` — must return the same path.
3. Even if SHA and branch match, a path mismatch means the agent is in the wrong
   worktree; the agent MUST STOP immediately.
4. Agents are **forbidden** from using `git -C <path>` or `Set-Location` to
   bypass the contract repository and operate in a different worktree.
5. `create-review-pack.ps1` enforces this check at the script level.

## Fixed process

1. GPT-5.6 writes a task contract that defines the baseline, branch, allowed
   files, banned operations, and acceptance criteria.
2. DeepSeek Agent verifies workspace path (see Workspace Path Enforcement above),
   then branches from `main` (or the contract-specified baseline) and
   makes changes in that isolated feature branch.
3. During development, DeepSeek runs targeted tests only for the module it is
   changing. It does **not** run the full test suite after every edit.
4. Once the final candidate commit is ready, DeepSeek runs the **complete**
   test suite required by the contract and saves the raw log output.
5. DeepSeek creates a local commit on the feature branch. The working tree
   must be clean after the commit.
6. DeepSeek runs `scripts/create-review-pack.ps1` with the parameters from the
   contract.
7. The script produces exactly one ZIP file outside the repository.
8. You (the human) upload that ZIP to GPT-5.6. You never run `git format-patch`,
   `git archive`, `zip`, or manually collect logs.
9. GPT-5.6 reviews the evidence and returns PASS or BLOCK.
10. If BLOCK, DeepSeek fixes the issues, reruns tests, commits, and regenerates
    a fresh Review.zip. The cycle repeats.
11. If PASS, you perform manual acceptance (run the app, check the tray icon,
    verify the UI) and merge.

## What the ZIP contains

| File | Purpose |
|------|---------|
| `manifest.md` / `manifest.json` | Task metadata: name, repo, branch, commit hashes, timestamp |
| `git-status.txt` | Full `git status --short --branch` at packaging time |
| `git-head.txt` | HEAD commit SHA |
| `git-log.txt` | One-line log from base to HEAD |
| `changed-files.txt` | File list between base and HEAD |
| `full-stat.txt` | Diffstat for the full change set |
| `full.patch` | Binary-safe full patch |
| `head.zip` | `git archive HEAD` snapshot of the entire repo at this commit |
| `test-summary.md` | Test summary provided by the caller (copied, not fabricated) |
| `logs/` | Raw test/validation log files (original names, original contents) |
| `incremental.*` | (optional) Incremental patch and stat if a previous HEAD is given |
| `artifact-info.txt` | (optional) Built `.exe` metadata with SHA-256 and PE header check |

## Important rules

- DeepSeek's text summary is **not** a substitute for the Review.zip. The ZIP
  is the sole review artifact.
- You are never expected to manually export patches, repo snapshots, logs, or
  compute SHA-256. If material is missing, the agent adds it.
- The Review.zip is **not** committed to Git.
- The Review.zip is **not** uploaded to GitHub Releases.
- Manual acceptance (running the app, visual checks) is always performed by a
  human. The agent cannot do it for you.
- Review ZIPs go to a fixed directory outside the repository (e.g.,
  `D:\QuackQuota-Review`). That directory is never inside the repo.

## Task completion definition

A task is **not complete** until ALL of the following are true:

- Final commit created on the feature branch
- Working tree clean (`git status --porcelain` empty)
- Contract-required tests have been run
- Raw log output saved to disk (outside the repo)
- `Review.zip` generated by `create-review-pack.ps1`
- `create-review-pack.ps1` self-validates the actual Review.zip it just generated
- `test-review-pack.ps1` (standalone regression suite using a temp repo) passes independently
- ZIP SHA-256 printed in the final report

## Reproducibility

Any reviewer can verify the pack by:

1. Extracting the ZIP
2. Comparing `manifest.json` hashes with the patches and archive
3. Running the same tests from `logs/`
4. Checking `full.patch` against the stated base
